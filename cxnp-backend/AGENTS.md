# CXNP Backend 协作规范

## 项目定位

本项目是基于 Spring Boot 和 MyBatis 的党建业务学习项目，当前以党员管理和 RBAC 权限管理为核心。

## 当前工程形态

当前采用单 Maven 工程、按业务模块分包的单体结构：

- `party`：党员业务。
- `rbac`：用户、角色、功能权限与数据权限。
- `organization`：党组织和支部业务。
- `common`：统一响应、异常、常量与通用工具。
- `config`：框架配置。

## 技术栈

- Java 17
- Spring Boot 3.3.5
- MyBatis XML
- MySQL 8
- Maven
- Lombok

## 分层规范

- Controller：接口入口、参数校验、响应封装；不得直接调用 Mapper。
- Service：业务规则、事务控制、数据权限二次校验。
- Mapper：数据库访问接口。
- Mapper XML：动态 SQL、多表关联 SQL。
- Entity：数据库实体。
- DTO：接口请求对象。
- VO：接口响应对象。

## 权限规范

- 功能权限统一使用 `permissionKey`，例如 `party:member:list`。
- API 功能权限与业务数据权限分层处理。
- 数据权限不能依赖前端传入的组织或支部范围。
- 用户—角色、角色—权限、角色—数据范围均通过关联表建模。
- 重要绑定关系需由 Service 前置校验与数据库唯一约束双重保证。

## 数据库规范

- 表名、字段名使用 `snake_case`；Java 属性使用 `camelCase`。
- 中间表增加必要的唯一约束和索引。
- 初始化数据与测试清理脚本统一放在 `sql` 目录。
- 复杂查询优先通过 MyBatis XML 管理。

## 验证规范

- 每个接口至少验证：正常结果、空结果、非法参数。
- 权限接口至少验证：有权限、无功能权限、无数据范围。
- 涉及多表写入时，验证事务回滚。
- 涉及重复绑定时，验证 Service 校验和数据库约束。

## 文档职责

- `AGENTS.md` 只记录项目定位、长期技术约束、协作规范和文档职责，不记录具体开发任务、任务进度或历史任务。
- `current-task.md` 只记录当前唯一活跃任务，包括任务目标、当前状态、当前 OpenSpec change（如适用）、当前任务项、完成标准和必要的当前任务上下文。
- 不在 `current-task.md` 中维护已完成任务历史、长期工程规划或与当前任务无关的备注。
- 未经用户明确确认验收，不得将当前任务标记为“已完成（验收通过）”。

## OpenSpec 协作流程

- 中型及以上变更必须先创建仓库内 `openspec/changes/<change-name>/` 变更包；适用范围包括跨模块或跨层实现、RBAC/认证/数据权限、数据库迁移或多表写入、接口行为变化，以及需要多种验收场景的业务需求。
- OpenSpec 变更包中，`proposal.md` 说明变更原因与范围，`specs/` 说明业务行为，`design.md` 说明技术方案，`tasks.md` 记录可验证的实施任务；已归档的稳定业务规格放在 `openspec/specs/`。
- 单字段修改、独立的小型 SQL 修复、无业务语义变化的格式或注释调整可以不创建 OpenSpec 变更包，但仍必须具有明确且可验证的完成标准。
- OpenSpec 变更工件完成后，必须等待用户审阅并明确允许实施；不得直接开始实现。
- 每次实施只允许执行 `tasks.md` 中一个未完成任务项。完成该项的修改和验证后必须停止，等待用户明确确认后才能开始下一项。
- 实施发现需求、范围或设计变化时，必须先更新相应的 OpenSpec 变更工件并重新等待用户确认，不得直接扩展实现。
- 所有任务完成后，必须等待用户明确验收；只有在用户明确允许后，才能同步规格或归档变更。
- 当前任务切换时，已验收任务不在 `current-task.md` 留存历史；其记录由 Git 历史和相应的 OpenSpec 归档保留。

## 后续工程演进

当前不拆分 Maven Module。

仅在模块需要独立复用、多人独立维护或构建隔离时，演进为：

- `cxnp-common`
- `cxnp-rbac`
- `cxnp-party`
- `cxnp-organization`
- `cxnp-app`

多 Maven Module 不等同于微服务；在保留单一启动模块时，系统仍是单体应用。
