# 当前任务：RBAC 功能权限校验

> 状态：未开始

在已完成登录认证和当前用户上下文的基础上，建立基于角色的功能权限校验能力。功能权限统一使用 `permissionKey`，为后续数据权限校验提供基础。

## 目标

建立“用户 → 角色 → 功能权限”的授权链路，并在接口入口完成权限校验。

目标链路：

当前登录用户 → 用户角色 → 角色功能权限 → 受保护接口

## 待办

- [ ] 设计并创建角色、功能权限、用户角色关联、角色权限关联的数据表及唯一约束、索引。
- [ ] 在 `sql` 目录补充初始化数据和测试清理脚本。
- [ ] 增加角色和功能权限的 Entity、Mapper 及 MyBatis XML 查询。
- [ ] 实现当前用户功能权限查询 Service，并在 Service 层完成权限二次校验。
- [ ] 为党员查询接口定义并接入 `party:member:list`、`party:member:detail` 功能权限。
- [ ] 实现接口权限校验机制，禁止无功能权限用户访问受保护接口。
- [ ] 统一处理无功能权限场景并返回明确的错误 JSON。
- [ ] 验证有权限访问场景。
- [ ] 验证已登录但无功能权限场景。
- [ ] 验证角色或权限重复绑定时的 Service 校验和数据库唯一约束。

## 完成标准

- [ ] 用户、角色、功能权限及两类关联关系均有清晰的数据模型和必要约束。
- [ ] 已登录且拥有对应 `permissionKey` 的用户可以访问受保护接口。
- [ ] 已登录但无对应功能权限的用户无法访问受保护接口，并收到统一错误 JSON。
- [ ] 重复绑定被 Service 校验和数据库唯一约束共同拦截。
- [ ] 已完成有权限、无功能权限和重复绑定场景验证。
