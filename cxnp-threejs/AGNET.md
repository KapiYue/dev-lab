# 项目学习与开发约定

## 项目目标

本项目用于巩固排水数字孪生场景中的 Three.js、Shader、Mapbox GL JS 和接口数据驱动能力。最终需要能够展示设备模型、管道水流动画、异常状态，以及基于真实地址的地下分层和剖面效果。

## 页面与技术边界

- `/`：城市监控页，当前使用高德地图进行城市设施定位。
- `/overview`：工程概览页，由 `OverviewPage` 加载 `MapboxOverview`。
  - 地图底图、工程覆盖区、道路/管线和设施点使用 Mapbox GL JS 图层。
  - 工程覆盖区来自 GeoJSON，通过 `fill` 和 `line` 图层渲染，不属于 Three.js 图层。
  - 重点设备模型通过 Mapbox custom layer 与 Three.js 共享 WebGL 上下文叠加。
- `/facility/:id`：设备级三维场景(重用threeJS)，由 `FacilityTwinScene` 提供，负责水泵、闸门、井盖、管道和设备交互预览。

## 三维实现原则

- 设备模型优先使用 GLTF；保持模型节点命名或同步更新节点查询逻辑。
- 单根管道先使用普通 Mesh 验证几何体、方向和材质，再使用 `InstancedMesh` 优化大量重复管道或井盖。
- 管道水流使用独立的 Shader 材质，外层管道与内部水流分层渲染。
- Shader 动画通过 uniform 驱动，不在每帧触发 React 状态更新。
- `instantFlow` 控制水流速度，`pumpRunning` 控制流动启停，`status/alarmLevel` 控制颜色、发光和异常效果。
- 停止或离线状态必须有明确视觉反馈；异常管段使用橙色或红色，不仅依赖文字提示。
- Mapbox 地质剖面先使用 3～5 层模拟土体完成坐标、透明度和剖切流程，再考虑接入真实地质数据。
- 真实地址可以提供位置和地图上下文，但真实地下土层需要额外的地质、钻孔或工程勘察数据，不能假设 Mapbox 底图自带这些数据。

## 数据流约定

监测数据 → 设施状态映射 → Three.js 场景属性和 Shader uniform。

主要映射关系：

| 数据 | 三维效果 |
| --- | --- |
| `instantFlow` | 水流速度、粒子速度 |
| `pumpRunning` | 水流启停、水泵旋转 |
| `gateOpening` | 闸门升降和流量表现 |
| `status` | 管道/设备基础状态颜色 |
| `alarmLevel` | 红橙色告警、发光或闪烁 |

## 开发顺序

### Three.js 管道学习顺序

1. 先用普通 Mesh 完成单个管道，验证位置、长度、旋转、透明材质和基础交互。
2. 将重复管道或井盖改为 `InstancedMesh`，验证共享 Geometry/Material 和批量渲染。
3. 最后增加实例级别的状态和颜色，让每个实例可以独立表达正常、预警、异常和停止状态。

相关对象的学习边界：

- 普通 Mesh：先验证单根管道。
- `InstancedMesh`：批量渲染重复管道或井盖。
- `TubeGeometry`：实现弯曲管道，放在直管验证之后。
- Shader 材质：实现水流、发光和告警效果，先作用于单个 Mesh，再扩展到实例。

完成上述管道路径后，再继续：

4. 将水流速度、启停和告警颜色接入当前监测数据。
5. 增加沿管道方向移动的蓝色粒子，并处理停止、异常状态。
6. 在粒子水流稳定后，补充透明管壁、更细的多条流线、Bloom 泛光与方向箭头等视觉增强；它是阶段 7 的后续子阶段，不改变地图阶段编号。
7. 在 Mapbox 工程概览中加入地下 3～5 层模拟地质体。
8. 增加基于真实地址的局部剖切，并预留真实高程/地质数据接入边界。

## 验证要求

每个阶段完成后至少执行：

```bash
npm run typecheck
npm test
npm run build
```

涉及视觉效果时，还要在浏览器中检查：正常流动、流量变化、停止运行、预警/严重异常、地图 2D/3D 切换和 WebGL 失败回退。

## 工作范围

除非当前任务明确要求，不要改动地图供应商、坐标转换策略、现有页面布局或接口数据结构。先完成可验证的小阶段，再进入下一阶段。
